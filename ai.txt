function markLessonComplete(courseId, lessonId) {
  const progress = loadProgress();

  if (progress.enrolledCourses[courseId] === undefined) {
    progress.enrolledCourses[courseId] = { completedLessons: [lessonId] };
  } else {

# LMS Project — Mentoring Summary & Roadmap

**Project:** Learning Management System ("LearnFlow")
**Stack:** HTML5, CSS3, JavaScript (ES6+), LocalStorage, JSON — no backend/framework
**Learner profile:** Comfortable with JS basics, working on strengthening DOM/events; building a skeleton-first, then-polish approach
**Timeline:** ~1–2 weeks

---

## Key Decisions Made

- **Visual identity:** Dark-and-blue color palette, implemented as CSS custom properties (`:root` for dark defaults, `[data-theme="light"]` override), with a working light/dark toggle persisted to `localStorage`.
- **File structure:** Static content (`courses`, `quizzes`) kept separate from dynamic user data (`userProgress`), matching a "content vs. state" split.
- **Data model shape:**
  - `courses`: array of course objects (`id`, `title`, `category`, `difficulty`, `description`, `lessons[]`).
  - `quizzes`: array of quiz objects linked to a course via `courseId`, each with a `questions[]` array (`text`, `options[]`, `correctAnswerIndex`).
  - `userProgress`: single object, nested per-course `completedLessons`, one **latest** quiz result per quiz (no history for now), separate `bookmarkedCourses` and `bookmarkedLessons` arrays.
- **Persistence pattern:** every stateful feature follows the same **load → mutate → save** pattern against `localStorage` (`JSON.parse`/`JSON.stringify`, with a sensible default when nothing is stored yet).
- **Authentication approach:** Since this is a pure front-end project, "login" is a **simulated session** — a `users` array in `localStorage` (name/email/password, explicitly *not* secure — worth a README note) plus a `currentUser` value marking who's "logged in." Protected pages will check `currentUser` before rendering and redirect to `login.html` if absent.
- **Page split:** `index.html` will become the public landing page only; the dashboard moves to its own `dashboard.html`, gated behind the simulated login.
